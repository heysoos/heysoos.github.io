# Portfolio Website

Personal portfolio for Sina Khajehabdollahi — computational neuroscientist and ALIFE researcher. The site is both a professional CV and a living gallery of WebGPU simulation art. Design philosophy: dark, minimal frame where simulations provide all the visual richness.

## Commands

```bash
npm run dev       # Astro dev server with hot reload
npm run build     # Static build → dist/
npm run preview   # Preview the built site locally
```

Deploys automatically to GitHub Pages on push to `main` via `.github/workflows/deploy.yml`.

## Stack

- **Framework:** Astro (static, no SSR)
- **Language:** TypeScript
- **GPU:** WebGPU with WGSL shaders
- **Styling:** CSS custom properties (theme system)
- **Content:** Astro content collections (Markdown)

## Simulations

Each simulation is self-contained in `src/components/simulations/<name>/`. The full pattern includes:

- **`<name>-controller.ts`** — WebGPU setup, buffers, render loop; exports `<Name>Controller` with `init(canvas)`, `start()`, `stop()`, `reset()`
- **`<name>-panel.ts`** — UI panel builder; exports `build<Name>Panel(container, controller, opts)` (boids uses `panel/` subdirectory instead — public API via `panel/index.ts` is unchanged)
- **`src/data/<name>-presets.ts`** — auto-generated preset array (do not edit manually)
- **`src/pages/admin/<name>.astro`** — dev-only preset editor; save endpoint is a Vite middleware in `astro.config.mjs`
- **`src/content/projects/<name>.md`** — gallery entry with `simulation: "<name>"` frontmatter

Register the controller in `src/pages/gallery/[...slug].astro` and optionally in `src/lib/webgpu/preview-registry.ts`.

Full conventions and implementation guidance: `docs/specs/`.

## Theme System

Active theme is set by a single import in `BaseLayout.astro`. To switch: change the import to a different file in `src/styles/themes/`. All colors are CSS custom properties — the key tokens are `--bg-primary`, `--bg-surface`, `--text-primary`, `--text-body`, `--accent`, `--accent-glow`.

## Gotchas

- WebGPU requires a secure context (HTTPS or localhost). The dev server runs on HTTP localhost, which is fine.
- Dynamic imports for WebGPU components use `client:only="react"` is NOT the pattern here — Astro island with `client:only` or inline `<script>` tags in `.astro` files.
- Gallery page uses dynamic imports with error handling to avoid SSR crashes (WebGPU is browser-only).
- `astro.config.mjs` has GitHub Pages base path configured — don't break this.
- Boids has a live in-browser shader editor (CodeMirror) — `reloadShader()` in the controller hot-swaps WGSL at runtime.
- Preset files in `src/data/` are AUTO-GENERATED by their admin pages — never edit them by hand.
- Admin save endpoints (`/api/admin/save-*`) are Vite dev middleware in `astro.config.mjs`. They only exist during `npm run dev`; admin pages are silently non-functional in production.
- There is no shared `fallback.ts` — WebGPU unavailability is handled inline in each controller.
- Boids audio drawer uses `<tr>` insertion (not div-append) — `DrawerController` manages disconnect lifecycle only; callers handle DOM insertion/removal themselves.
- Custom presets live in localStorage (`presets:<sim>`, trash in `presets:<sim>:trash`); built-ins stay in `src/data/`. Promote a phone preset by exporting JSON from the gallery page and importing it on the admin page. Preset files carry `format`/`version`; bump `FORMAT_VERSION` only on breaking shape changes and add a `MIGRATIONS` entry.
- Phone layout (`max-width: 768px`) swaps `PanelManager` for `BottomSheetController`; field-boids clamps loaded presets to `PHONE_PARTICLE_CAP` on phones.
- Param locks (`lib/presets/param-locks.ts`, localStorage `presets:<sim>:locks`): alt-click or long-press a slider row. The preset manager pins locked keys to the controller's current value inside `prepare`, so loads keep them and the dirty check ignores them; Randomize (uniform over each slider's range, from the spec) restores them after rolling. Sliders only; pills/toggles are not lockable.
- On coarse pointers `createRangeSlider` makes the native input display-only and drives it with a relative horizontal drag on the row (vertical movement scrolls). Don't re-enable pointer events on `.touch-passive`.
- Field-boids display is a three-pass chain in `field-post.wgsl`: base (density → linear colour with curve/palette/bloom, blended with the previous frame for render-only long exposure, into a canvas-sized rgba16float), optional additive points, then tonemap to the swapchain. `curve/tonemap/palette/bloom/longExposure` are preset params; `field-boids-spec.ts` is the single list of params the desktop Look section and the phone scrub list are built from. The accumulation target carries flow colour in rgb and a scalar intensity in a, so Points view (instanced shaped sprites, `pointSize`/`pointShape`) goes through the same curve/palette/tonemap. The uniform block is 176 bytes.
- Phone sim pages are immersive (`sim-page.css` phone block + `gallery/[...slug].astro`): nav padding removed, viewport is `100dvh`, `body.sim-immersive` slides the nav away while the canvas is in view, and the ︾ button (`#scroll-down`) scrolls to the write-up since the canvas eats vertical drags. Only ⚙ shows at rest; pause/reset/fps appear with `.sim-viewport.scrub-open`; fullscreen is hidden on phones.
- Phone field-boids UI is `lib/sim-page/scrub-panel.ts`: grouped list card over the canvas (header: undo/redo/Presets; ⚙ toggles it and reads × while open). A sideways drag on a numeric row scrubs it in place (`ROW_PX` for the full range; vertical still scrolls, the click is swallowed). Selecting a param hides the list and shows `.scrub-chip` (name, value, range, ‹ back); drag the canvas to change it, a plain tap (no movement) or ‹ returns to the list, tapping the chip name toggles its lock. The card header (undo/redo, Presets ›, ⚄ Randomize) stays put while the body scrolls; Presets › swaps the body for the shared preset section inside the same card (`.presets-mode` widens it). Tilt and gravity are a last "Device" group in the list whose keys (`tiltGravity`, `gravity`) the setup routes to the sensor / `ctrl.gravity` instead of `ctrl.params`. A plain tap on the canvas with the list open closes it. The bottom sheet is never shown on phones; slider/toggle styles are scoped to `:is(.params-panel, .scrub-presets)`. Enum specs carry a `ui` (segmented/swatches/select) and `showIf`; both UIs honour them.
- Field-boids gravity is a device setting, not a preset param: `ctrl.gravity` (strength, localStorage `field-boids:gravity`) and its direction (straight down, or steered by `lib/sim-page/tilt-sensor.ts`) both live in the phone-only tilt row. Presets never carry it and Randomize never touches it. Desktop has no gravity UI. Keep `field-common.wgsl` offsets and `packUniforms()` in sync.
- `boids-controller.ts` tick() is a coordinator: `_preFrameSetup → _packUniforms → _runComputePasses → _renderFrame`. Private helpers are in the same file.
